# Phase 2 test runner: Power/Audio steps (Automation/AppTest.py port).
# Optional at import time (backend/power_supply_service.py and
# audio_service.py degrade gracefully if these aren't installed or no
# hardware is attached), but required to actually exercise those steps.
pyvisa>=1.16        # programmable power supply (SCPI over VISA)
# A real user hit VI_ERROR_LIBRARY_NFOUND (-1073807202, "A code library
# required by VISA could not be located or loaded") on some Windows/NI-VISA
# combinations with pyvisa 1.14 (confirmed 2026-08-26); bumping to 1.16 fixed
# it for them. The exact root cause (likely an improvement in pyvisa's VISA
# library discovery logic) hasn't been cross-checked against pyvisa's own
# release notes, but 1.16 is the minimum version confirmed to work.
# pyvisa itself is just the API -- it needs a VISA backend to actually talk to
# an instrument. NI-VISA (proprietary driver, separate installer) provides
# one, but pyvisa-py is a pure-Python backend installable via pip, no driver
# needed. Without either, pyvisa.ResourceManager() fails on connect with
# "No IVI/VISA implementation found... install pyvisa-py" -- reported on a
# fresh machine with no NI-VISA installed (2026-08-25, see Requirement.md).
pyvisa-py>=0.7
# Using a directly USB-connected power supply (USBTMC) via pyvisa-py needs
# pyusb plus an actual libusb backend (libusb-package bundles the right OS
# libusb binary). That alone isn't enough on Windows -- the device's driver
# also has to be swapped for a libusb-compatible one (WinUSB etc.) with a
# tool like Zadig before it's actually recognized; these pip packages are
# just the prerequisite, the driver swap is a separate manual step.
# If NI-VISA is used instead (it has its own built-in USBTMC driver), these
# two packages aren't needed and are simply unused even if installed
# (2026-08-25, see Requirement.md).
